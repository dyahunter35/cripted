# إضافة البودكاست يدوياً

التسجيلات الصوتية ونصوصها يضيفها صاحب المشروع يدوياً. لا يولّد التطبيق أو البناء أو النشر بودكاست أو حواراً، ولا تُستدعى خدمات Gemini أو توليد الصوت.

## إضافة تسجيل أو استبداله

1. ضع الملف الصوتي الذي أعددته داخل `public/audio/`، مثل `aes_podcast.m4a`.
2. حدّث مدخل الخوارزمية في `src/content/podcasts.json` يدوياً: اسم الملف `audioFile`، والعنوان، والمدة، والنص المفرّغ وتوقيته إن توفر.
3. افحص البيانات بالأمر:

   ```bash
   npm run check:podcasts
   ```

هذا فحص قراءة فقط: يتأكد من وجود التسجيل وبيانات النص دون تعديل الملفات أو الاتصال بخدمات خارجية. مسار النشر يستخدم الفحص نفسه.

## سلوك المشغل

- لا يحمّل الصوت أو بياناته الوصفية عند فتح الصفحة؛ يستخدم `preload="none"` ويترك `src` غير معيّن حتى الضغط على Play.
- النقر على النص يحدد موضع الاستماع، ثم يبدأ الصوت عند الضغط على Play.
- الكاش يحفظ نسخة من **التسجيل الذي أضفته** بعد بدء الاستماع أو عند الضغط على زر الحفظ؛ لا يولّد تسجيلاً جديداً ولا يغيّر الملف الأصلي.

سكربتات المعالجة القديمة في `scripts/` أدوات مستقلة لا يشغّلها البناء أو النشر. لا تُشغَّل أدوات التوليد أو إعادة التفريغ لتعديل التسجيلات والنصوص اليدوية دون طلب صريح من صاحب المشروع. مدخل `generate-podcasts.ts` القديم أصبح فحصاً للملفات فقط، ولا يحتوي على توليد أو كتابة بيانات.
